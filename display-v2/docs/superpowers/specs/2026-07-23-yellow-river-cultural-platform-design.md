## 一、项目概述

### 1.1 项目背景

黄河文脉数字文化平台是一个以古诗词为核心、融合黄河沿岸山东段九城文化的数字化展示平台。目前已完成基础框架搭建，包括诗人展示、诗词详情、城市专题、历史时间线等模块，以及 12 张青绿山水国画素材。

## 二、需求详细设计

### 2.1 诗人信息管理

#### 2.1.1 现状分析

- 后端 seed 数据仅 6 位诗人，生产库约 130 位
- `completeness` 计算权重：biography(20) + real_avatar(15) + anime_avatar(15) + style(15) + birthplace(10) + birth_year(10) + poem_count(15)
- 目前仅约 7 位有 biography，0 位有 style
- 冷门诗人（completeness < 40）已筛除

#### 2.1.2 需求

| 优先级 | 需求 | 说明 |
|---|---|---|
| P0 | 冷门诗人筛除 | 已完成，completeness < 40 的诗人不展示 |
| P1 | 数据补全 | 通过管理后台补充 biography、style 等字段 |
| P1 | 头像管理 | 支持真实头像 + anime 头像双版本 |
| P2 | 批量导入 | 支持 Excel 批量导入诗人数据（已有） |

#### 2.1.3 数据补全建议

建议按以下优先级补全诗人数据：

1. **核心字段**：name, dynasty_id, birth_year, death_year（基础信息）
2. **展示字段**：avatar_url, avatar_anime_url（视觉效果）
3. **内容字段**：biography, style（丰富度）
4. **关联字段**：poem_count（自动计算）

### 2.2 前端整体美观设计和布局

#### 2.2.1 设计风格

采用**混合式**设计风格：

| 页面类型 | 风格 | 说明 |
|---|---|---|
| 首页 | 沉浸式 | 全屏滚动叙事，每屏一个主题 |
| 列表页 | 信息密度型 | 卡片网格，数据紧凑展示 |
| 详情页 | 杂志风 | 大图+留白+文字穿插 |
| 可视化面板 | 科技风 | 暗色主题+霓虹高亮+3D 地图 |

#### 2.2.2 布局优化

**问题**：目前数据展示布局不够美观，背景单调

**解决方案**：

1. **背景层次化**
   - 添加渐变背景（从深到浅）
   - 添加纹理叠加（纸张纹理、水墨纹理）
   - 添加微妙的动画效果（粒子、光影）

2. **数据展示优化**
   - 统一卡片样式（圆角、阴影、边框）
   - 添加数据可视化元素（统计数字、进度条、标签云）
   - 优化文字排版（字体、行高、间距）

3. **响应式设计**
   - 移动端适配（卡片单列、图片自适应）
   - 平板适配（双列布局）
   - 桌面端（多列网格）

#### 2.3.3 数据展示优化

每个模块展示的数据：

**第一屏：RiverHero**
- 核心标语（如"黄河之水天上来"）
- 项目简介（一句话）

**第二屏：RiverCityRail**
- 城市名 + 代表景点数 + 关联诗词数
- 黄河曲线示意图

**第三屏：DynastyRail**
- 朝代名称 + 年代范围

**第四屏：FeaturedPoetCard**
- 诗人头像（真实/动漫）
- 名字 + 朝代
- 代表作一句

- 点击进入诗人详情

**第五屏：FeaturedPoemCard**
- 诗词标题 + 作者
- 名句（1-2 句）
- 关联景点
- 点击进入诗词详情

**第六屏：StatTicker**
- 统计数字（诗人总数、诗词总数、景点数、朝代跨度）

### 2.4 AI 诗词陪学助手

#### 2.4.1 功能定位

在诗词详情页嵌入 AI 助手，作为用户的"陪学助手"，帮助用户深入理解诗词。

#### 2.4.2 功能设计

| 功能 | 说明 |
|---|---|
| 位置 | 诗词详情页右侧或底部固定区域 |
| 上下文 | 自动加载当前诗词信息作为 AI 上下文 |
| 交互方式 | 用户主动提问，AI 回答 |
| 回答范围 | 自由问答，但以当前诗词为优先上下文 |
| 对话历史 | 不保存，刷新页面后清空 |

#### 2.4.3 UI 设计

```
┌─────────────────────────────────────────────┐
│ 诗词详情页                                     │
├──────────────────────────┬────────────────────┤
│                          │  🤖 诗词助手        │
│  诗词标题                 │                    │
│  作者 / 朝代              │  [对话区域]         │
│                          │                    │
│  诗词内容                 │  用户：这首诗的      │
│  （大字展示）              │  意境是什么？       │
│                          │                    │
│  注释                     │  AI：这首诗通过...  │
│  创作背景                 │                    │
│                          │  [输入框] [发送]    │
│  关联景点                 │                    │
│                          │                    │
└──────────────────────────┴────────────────────┘
```

#### 2.4.4 技术实现

- 复用现有 `/api/public/chat` 接口（DeepSeek SSE 流式）
- 前端发送消息时附加当前诗词 ID 作为上下文
- 后端在 system prompt 中注入诗词详情

#### 2.4.5 提示词设计

```
你是一位古诗词陪学助手。用户正在学习以下诗词：

【诗词标题】{title}
【作者】{poet_name}（{dynasty}）
【内容】{content}
【注释】{annotation}
【创作背景】{background}
【关联景点】{spot_name}

请根据这首诗词的内容，回答用户的问题。如果问题超出这首诗词的范围，
可以适当扩展，但优先围绕这首诗词展开。回答要通俗易懂，适合学生学习。
```

### 2.5 AI 写诗交互小游戏 —— 「诗意画境」

#### 2.5.1 核心概念

用户选择主题 → AI 生成诗词 → 进入沉浸式意境场景 → 互动探索 → 学习奖励

#### 2.5.2 玩法流程

```
┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│  主题选择    │ →  │  AI 作诗    │ →  │  意境展开    │ →  │  互动探索    │
│  （输入/选择）│    │ （流式生成） │    │ （场景切换） │    │ （点击元素） │
└─────────────┘    └─────────────┘    └─────────────┘    └─────────────┘
                                                                ↓
                                                        ┌─────────────┐
                                                        │  书写动画    │
                                                        │ （毛笔效果） │
                                                        └─────────────┘
```

#### 2.5.3 主题选择

提供预设主题 + 自定义输入：

| 预设主题 | 关键词 | 意象元素 |
|---|---|---|
| 黄河 | 黄河、奔流、九曲 | 河水、山川、船只 |
| 明月 | 月亮、思乡、团圆 | 明月、星空、庭院 |
| 春天 | 春风、花开、生机 | 花瓣、燕子、柳树 |
| 离别 | 送别、思念、远行 | 长亭、古道、夕阳 |
| 边塞 | 战争、壮志、苍凉 | 大漠、孤烟、长河 |

#### 2.5.4 意境场景

AI 生成诗词后，进入沉浸式场景：

- **背景**：水墨渐变 + 粒子效果（花瓣飘落、河水流动）
- **文字**：逐字显现 + 墨迹晕染动画
- **意象元素**：诗词中提到的意象以可点击元素呈现
- **交互**：点击元素触发详情弹窗

#### 2.5.5 互动探索

点击场景中的意象元素，触发：

| 交互 | 内容 |
|---|---|
| 意象解释 | 该意象在古诗中的常见用法 |
| 相关名句 | 包含该意象的其他名句推荐 |
| 书写动画 | 该意象汉字的毛笔书写动画 |

#### 2.5.6 技术方案

| 技术 | 用途 |
|---|---|
| Canvas/WebGL | 粒子效果、场景动画 |
| GSAP | 文字动画、过渡效果 |
| CSS Animation | 简单动画、悬停效果 |
| DeepSeek API | AI 生成诗词 + 意象解析 |

#### 2.5.7 页面路由

- 独立页面：`/games/poetry-scene`
- 首页入口：第六屏数据概览模块

## 五、风险与注意事项

### 5.1 数据风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 诗人数据不完整 | 展示效果差 | 优先补全核心诗人数据 |
| 民俗数据收集困难 | 拓展进度慢 | 先做框架，逐步补充数据 |
| AI 生成内容质量 | 用户体验差 | 优化提示词，添加人工审核 |

### 5.2 技术风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 3D 地图性能 | 页面卡顿 | 优化模型面数，使用 LOD |
| 大屏适配 | 不同屏幕显示异常 | 使用 autofit.js 统一缩放 |
| 关系图谱数据量 | 渲染慢 | 限制同时展示节点数 |

### 5.3 设计风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 风格不统一 | 视觉混乱 | 建立设计规范，统一组件库 |
| 动画过多 | 性能差 | 控制动画数量，提供关闭选项 |
| 移动端适配 | 体验差 | 优先移动端设计，渐进增强 |
