## 收尾数据大屏两项遗留（分支 `feat-datav-overhaul`，提交 30e4d69 + 4edb150）

### ① 九城顺序改为后端驱动
- `PublicSpotController.regions()` 返回的顺序即「上游→下游」，前端改为消费它，
  `FALLBACK_REGION_ORDER` 只在该接口不可达时兜底。后端加城市前端无需改动。
- 顺手修掉该接口的 N+1：原先逐区域 `list(1,1,null,region).getTotal()` 共 9 次 COUNT，
  改为「一次只 select region 列 + 内存分组」（`SpotService.countByRegion()`）。

### ② 五脉文华支持按城市下钻
- **文化条目表有 `region` 列（NULL = 全域性内容），但没有朝代字段**——
  所以五脉只随城市变，不随朝代变。
- `CulturalItemService.categoryStats(String region)` 加可选区域参数；
  `/api/public/cultural/categories?region=济南` 即可下钻。全域口径不含 NULL 区域条目。
- 前端 SWR key 改成 `cultural-categories:<region|all>`，各城市独立缓存，来回点不重复请求。
- 五脉里的「古诗词」格也改成只按城市收窄，与其余四格口径一致；
  否则同一张卡里一半跟朝代变、一半不跟。
- 朝代筛选生效时卡片标注显示「<城市> · 不含朝代」，把口径差异写明。

## 环境笔记（本次踩到的）

### 后端构建：必须用 JDK 17，且用 IDEA 内置 Maven
```bash
export JAVA_HOME="D:\\app\\jdk\\17"          # 见下：JBR 是 Java 25，Lombok 不工作
export PATH="$JAVA_HOME/bin:<PortableGit>/mingw64/bin:<PortableGit>/usr/bin:/c/Windows/System32"
cd backend
"/d/app/idea/IntelliJ IDEA 2026.1.2/plugins/maven/lib/maven3/bin/mvn.cmd" -o test
```
- `mvn` 不在 PATH，`mvnw` 不存在；IDEA 内置 Maven 可用（`mvn.cmd`，不是 `mvn` 脚本——
  bash 脚本在 Git Bash 下会报 `找不到主类 org.codehaus.plexus.classworlds.launcher.Launcher`）。
- **不要用 IDEA 的 JBR**（`/d/app/idea/IntelliJ IDEA 2026.1.2/jbr` 是 Java 25）：
  Lombok 注解处理不生效，会在**未改动的文件**里报一堆「找不到符号 getXxx()」，
  极易误判成自己改坏了。本机可用 JDK：`/d/app/jdk/{11,17,21}`。
- `.m2/repository` 已存在，加 `-o` 离线跑即可。

### 其它
- **本会话出现过 PATH 被清空**（`dirname/grep/head: command not found`）。
  命令开头显式 `export PATH=...` 即可恢复。
- **托管 node 目录版本号变了**：`22.22.2-2` → `22.22.2-3`。
  写死的路径会突然失效，用前先 `ls .../node/versions/`。
