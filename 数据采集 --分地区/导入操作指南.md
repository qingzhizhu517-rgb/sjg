# SJG 数据批量导入 — 详细操作指南

> 目标：将全部 Excel 数据 + 媒体文件导入数据库，图片/视频上传 OSS，实现前端回显。

---

## 前置条件检查

```bash
# 1. 确认 Python3 可用（macOS 自带）
python3 --version

# 2. 确认 openpyxl 已安装（读 Excel 用）
python3 -c "import openpyxl" || pip3 install openpyxl

# 3. 确认 oss2 已安装（上传 OSS 用）
python3 -c "import oss2" || pip3 install oss2

# 4. 确认数据库可连接
mysql -u 你的用户名 -p -h 47.104.207.58 -e "SELECT 1" sjg
```

---

## 第一步：预览数据（不上传 OSS，不写数据库）

```bash
cd "/Users/a1/develop/vibecoding/sjg/数据采集 --分地区"
python3 import_data.py --sql-only
```

这一步只做两件事：
- 读取 8 个 Excel，解析 198 条记录
- 生成 `sjg_import.sql`（纯 SQL 文件，不连接数据库）

**运行完后检查输出**，确认：
- `景点数: 70` — 是否符合预期
- `诗人: 130` — 是否有不该出现的名字
- `诗词: 195` — 数量对不对
- `待上传文件: 176 个` — 媒体文件数是否正确

输出的 SQL 文件在当前目录下的 `sjg_import.sql`，可以打开看一眼确认结构。

## 第二步：处理朝代映射问题

脚本运行完后会发现，有些作者的朝代不在现有 dynasty 表（id=1~8）里，比如：

| 朝代 | 问题 | 
|------|------|
| 金代 / 金 | dynasty 表没有 id=9 |
| 现代 / 当代 / 近现代 | 需要决定归到哪 |

**建议**：在 sjg.sql 的 dynasty 部分补充一条：

```sql
-- 在原 sjg.sql 的 dynasty INSERT 后面加
INSERT INTO dynasty (id, name, start_year, end_year, description) VALUES
(9, '金代', 1115, 1234, '金朝时期');
```

如果现代作者很少，直接归到 id=8（清代）也行，手动改一下 SQL 里的 dynasty_id。

## 第三步：修复 Excel 里的数据问题（可选）

脚本自动解析，但 Excel 原始数据可能有不一致的地方。建议快速过一遍：

1. **经纬度异常**：有些记录经度写了 `117.015833` 但实际上是其他地方的坐标（不同 Excel 模板复制了模板数据），可在生成的 SQL 里搜索这些异常值手动改
2. **诗人名称不一致**：如"王士禛"和"王士祯"可能是一个人，脚本会去重为两个诗人
3. **同名景点不同区域**：如"大明湖"在济南和泰安 Excel 中都出现，脚本只保留一个

## 第四步：备份 + 清空数据库

```bash
# 备份当前数据库（如果已有数据）
mysqldump -u 你的用户名 -p -h 47.104.207.58 sjg > sjg_backup_$(date +%Y%m%d_%H%M%S).sql

# 清空诗词/诗人/景点表（保留 dynasty 表）
mysql -u 你的用户名 -p -h 47.104.207.58 sjg -e "
  SET FOREIGN_KEY_CHECKS = 0;
  TRUNCATE TABLE poem_event;
  TRUNCATE TABLE poem;
  TRUNCATE TABLE event;
  TRUNCATE TABLE scenic_spot;
  TRUNCATE TABLE poet;
  SET FOREIGN_KEY_CHECKS = 1;
"
```

## 第五步：导入数据库结构（如果全新部署）

如果数据库当前是空的，先建表：

```bash
# 只建表，不插数据（sjg.sql 里已经有 CREATE TABLE）
mysql -u 你的用户名 -p -h 47.104.207.58 sjg < sjg.sql
# 注意：sjg.sql 里也包含了 INSERT 旧数据，会先清表再插旧数据
# 如果只需要表结构，先手动去掉 INSERT 部分
```

如果已经有表结构，跳过这一步。

## 第六步：上传媒体文件到 OSS

设置 OSS 凭证并运行脚本：

```bash
export OSS_ACCESS_KEY_ID=你的AccessKeyId
export OSS_ACCESS_KEY_SECRET=你的AccessKeySecret

cd "/Users/a1/develop/vibecoding/sjg/数据采集 --分地区"
python3 import_data.py
```

这次脚本会：
1. 读取 Excel + 扫描媒体文件（和 `--sql-only` 一致）
2. **批量上传 176 个文件到 OSS**（约需 2-5 分钟）
3. 生成带完整 OSS URL 的 SQL

上传进度每 20 个文件打印一次。

---

## 第七步：导入数据到数据库

```bash
mysql -u 你的用户名 -p -h 47.104.207.58 sjg < sjg_import.sql
```

因为脚本生成的 SQL 用 `START TRANSACTION` 包裹：
- 要么全部插入成功
- 要么全部回滚（不会出现插一半的情况）

如果报外键错误，说明某个 dynasty_id 在 dynasty 表中不存在，回头检查第二步。

## 第八步：验证

```bash

mysql -u 你的用户名 -p -h 47.104.207.58 sjg -e "
  SELECT 'poet' AS tbl, COUNT(*) FROM poet
  UNION ALL SELECT 'scenic_spot', COUNT(*) FROM scenic_spot

  SELECT id, name, image_url FROM scenic_spot LIMIT 5;

# 用浏览器打开一个 OSS URL，确认能访问
```

## 第九步：修正自增 ID

导入后自增 ID 可能不对，手动修正：

```bash
mysql -u 你的用户名 -p -h 47.104.207.58 sjg -e "
  ALTER TABLE poet AUTO_INCREMENT = $(mysql -u 你的用户名 -p -h 47.104.207.58 sjg -sN -e "SELECT MAX(id)+1 FROM poet");
  ALTER TABLE scenic_spot AUTO_INCREMENT = $(mysql -u 你的用户名 -p -h 47.104.207.58 sjg -sN -e "SELECT MAX(id)+1 FROM scenic_spot");
  ALTER TABLE poem AUTO_INCREMENT = $(mysql -u 你的用户名 -p -h 47.104.207.58 sjg -sN -e "SELECT MAX(id)+1 FROM poem");
"
```

或者直接用脚本生成的 SQL 里末尾的 `ALTER TABLE ... AUTO_INCREMENT = ...` 语句（已经在 sjg_import.sql 末尾）。

## 常见问题

| 问题 | 原因 | 解决 |
|------|------|------|
| `Unknown column 'xxx'` | 表结构可能和后端 entity 定义不一致 | 检查 sjg.sql 的建表语句，确认字段名 |
| 外键约束错误 | dynasty_id 不存在于 dynasty 表 | 先补全 dynasty 表（第二步） |
| OSS 上传失败 | AK/SK 不对或没有写入权限 | 检查环境变量，确认 Bucket 权限 |
| 图片裂图 | OSS URL 路径不对 | 用浏览器打开 URL 验证，手动修改 |
| Python 报 `ModuleNotFoundError` | 缺少依赖 | `pip3 install openpyxl oss2` |
