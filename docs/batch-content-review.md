# 管理端批量审核

1. 打开「来源与审核」，切换「审核队列」。默认筛选「待审核」，可按实体类型筛选。
2. 核验内容和关联来源后，勾选当前页的多条记录。仅待审核记录可勾选；翻页、筛选或刷新会清除选择。
3. 可填写批量审核备注，点击「批量通过并发布」并确认。每批最多100条；成功条目无需再单独点击发布。
4. 查看处理结果：显示本批成功/失败数量、每条的实体类型与ID、发布结果或失败原因。缺来源或记录已变更时，修正并重新选择待审核条目。
5. 请求超时或网络失败时，处理结果可能尚未确认。先刷新队列核对哪些条目已发布，再决定重新提交，不能把网络失败当成全部未处理。

每条数据独立提交事务，失败条目保留原审核状态，不影响其他成功条目。成功数据通过现有公开API发布给展示前端和大屏；有来源的内容才进入公开AI证据检索；用户端下一次取数即可读取，不需要重新部署前端。已打开页面仍使用原有缓存/刷新策略，可刷新页面查看最新数据。

本功能涵盖内容审核队列中的诗词、诗人、景点、历史事件、文化条目、朝代、诗词赏析和诗人关系。学习任务维持独立发布规则。本轮代码修改不等于已部署到线上，也不自动审核现有生产数据。

接口和事务说明见 [设计约定](superpowers/specs/2026-10-12-batch-content-review-design.md)。

验证记录：Java17下完整质量门禁通过；192项后端单元/MVC、7项真实MySQL集成、251项展示端单测及17项管理端契约/组件测试通过。审核队列的选择、确认和部分失败结果已在浏览器操作验证；批量结果状态加入仓库级axe门禁。

线上管理端Network Error排查：2026-10-12在Ego Lite复现，管理员令牌有效，但管理路径OPTIONS返回401且缺少CORS响应头。修复以最高优先级注册已有CorsFilter，保持精确域名白名单与管理员鉴权。新增真实HTTP测试验证预检200、匿名业务请求401且有CORS头、非白名单来源403；发布验收同时检查管理路径带Authorization/Content-Type的预检及401响应的CORS头。

## 来源待补充发布

批量接口新增 `allowUnreferenced`（默认false）。管理员必须显式勾选并确认，才允许缺少来源的待审核数据发布。每条保存 `[来源待补充]` 审计备注；不创建虚构引用。详情页显示来源待补充说明，所有未关联来源的条目均排除于AI证据检索。普通单条发布和默认批量发布仍要求来源。补充真实来源后，详情页自动展示引用。

该选项由用户在2026-10-12授权，用于公开现有存量资料；公开可浏览不代表出处已核验。
