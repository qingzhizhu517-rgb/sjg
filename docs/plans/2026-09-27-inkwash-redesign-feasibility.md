# 参考图水墨册页风格重构可行性评估

日期：2026-09-27。依据：用户提供的四张参考图、当前工作区源码及本地素材目视检查。

## 结论与本次交付状态

**可行，推荐在现有 `display-v2` 上重构展示层。** 当前已经具备 Vue 3、单一水墨主题、城市/景点/诗人/诗词路由、图表和公共接口。真正的工作量主要来自页面构图、统一插画、内容校核和移动端适配。

仅修改配色和字体无法达到参考效果。参考图的特点是“淡彩水墨插画融入宣纸底的文化册页”，而现有页面仍较依赖独立大图、卡片与三维沙盘。应保留取数、路由、缓存和审核机制，重组公共样式与四类重点页面。

本次已完成源码分析、已有素材检查、实施范围和新素材规格。**尚未生成任何新图片，也未改动应用代码。** 用户明确要求不使用 arkcli 及其技能；后续遵守此约束。当前会话未开放可调用的原生图片生成工具，因此新素材制作尚未完成。现有图片不计作本次生成成果。

这是静态代码层面的评估；没有启动完整应用、验证线上数据数量或实测加载性能。本地后端 8080 当前未运行。以下时间和性能数值均为规划估算或验收目标，不是实测结果。

## 参考风格应如何落地

| 设计要素 | 参考图的关键特征 | 项目中的实现方式 |
| --- | --- | --- |
| 底色 | 接近米白的浅宣纸，纸纹很弱 | 从现有 token 调整；建议试色 `#F5F2EB`，纹理单独低透明度铺底 |
| 文字 | 大标题有书卷感，正文更接近宋体 | 正文以清晰宋体为主，书法只用于短标题；优先本地授权字体及子集 |
| 色彩 | 墨褐文字、淡青绿山水、少量朱红与赭金 | 统一调色；分类图表颜色另设语义，不与按钮强调色混用 |
| 构图 | 大幅侧景或人物与正文并置，留白连接各区 | 用 Grid 重排布局，让图片边缘自然融入背景 |
| 卡片 | 细线、轻底色、弱阴影 | 共用册页卡组件，减少厚边框和明显悬浮效果 |
| 图片 | 独立插画、有雾化留白，不是完整海报截图 | 新图输出无文案插画，文字、按钮、数字、图表由页面绘制 |
| 动效 | 安静、缓慢、服务阅读 | 少量淡入和轻微位移；保留减少动态效果的系统偏好支持 |

所有交互文字应可选择、可搜索，按钮可键盘操作。小字不照搬参考图的实际像素尺寸，正文建议至少 16px；不能靠降低文字对比度制造“淡雅”。

## 可复用基础与需要谨慎处理的内容

### 技术基础

- 保留 Vue 3、Vite、Vue Router、axios 及公共 API，不需要更换框架。
- 保留 ECharts，用来实现可点击、可筛选的情感图；不能将曲线和统计数字烘焙到图片。
- 复用已有图片解析、数据适配、缓存、骨架屏、空态和错误态。
- 首页已有三维引擎可保留为扩展体验。若主视觉改为静态插画，三维依赖应延迟加载，避免同时争夺首屏资源。
- 公共主题目前已固定为 `inkwash`，无须重新建立多主题系统。

### 地图：艺术构图与真实地理数据分别处理

主插画可以表现黄河由山东流向入海口的视觉叙事，但生成图不能提供准确行政边界、河道或城市坐标。

若首页是艺术导览，可采用“插画 + 经过校准的相对位置链接”，并提供完整城市列表。若需要真实地理查询，应以 GeoJSON/坐标为底层，通过程序绘制边界与河流，再叠加绘画纹理。艺术导览与地理视图应说明各自用途。

### 情感图：保留视觉意图，重新定义统计口径

当前 `SpotDetail.vue` 的曲线采用前端固定映射：例如“豪放 92、婉约 40、悲凉 16”，缺失或未知标签默认 55，然后按朝代取均值。这是规则映射的示意值，不是经校准的情感强度。

目前环形图的分母是**全部情感标签出现次数**，分子是某标签次数，最后只显示前五项。因此它不是“某种情绪的诗词占全部诗词比例”，五项也不一定合计 100%。当前朝代序列到清代，不能凭参考图补出近现代数据。后端 AI 赏析的 `sentiment` 也只是文字。

建议第一版展示可核查的朝代篇数和情感标签分布。需要保留波澜曲线时，明确标为“基于标签规则的情感意象示意”，提供规则、篇数和来源，缺失标签不自动当作中性。豪放、婉约、淡泊等类别没有天然的高低顺序，正式分析可优先采用分类比例随朝代变化的图表。

若要真正量化跨时代情绪，需要单独定义分类体系、样本来源、作品时间依据、标注/模型版本与人工审核方式。这属于内容分析功能扩展，不宜隐藏在视觉改造中。

### 内容：页面丰富程度取决于已发布资料

城市资料、诗人的字/号/生平节点、部分景点历史与玩法，目前存在前端补充字典；后端尚无独立城市实体及完整对应字段。字典可以作为迁移输入，但不能自动认定为已审定史料。

公开接口只返回审核为 `published` 的内容。V27 将历史实体初始化为待审，发布要求来源关联。因此历史文档的景点、诗人、诗词总数不能当作当前可展示数量。需要先核对可展示数据，再决定首页卡片、人物生平节点和景点册页的实际数量。

参考图里的杜甫生平、诗词归属、景点名称和数字也都应作为设计示例，不能直接写入正式数据库。

## 推荐方案、顺序与工作量

| 方案 | 收益 | 局限 | 建议 |
| --- | --- | --- | --- |
| 仅调整颜色、字体与边框 | 改动较小 | 难以形成参考中的册页构图和画面融合 | 适合短期整理，不足以达到目标 |
| 保留业务、重构重点展示层 | 能实现四图主要视觉语言；复用现有路由和数据 | 需要重排页面、统一插画并补少量内容结构 | **推荐** |
| 前后端整体重写 | 能重新设计所有数据和交互 | 与当前目标相比成本高，已有能力需重新验证 | 当前没有必要 |

建议执行顺序：

1. 核对四类页面的已发布数据和内容来源；定下字体、留白、颜色及图片边缘规范。
2. 生成并校核四张素材试样；先完成杜甫或大明湖一页，验证图文融合和手机布局。
3. 将通过验证的结构提炼为公共导航、册页卡、侧景容器和分区标题。
4. 完成其余三类页面与首批素材；首页艺术导览采用独立可点击热区。
5. 按确定的口径补充朝代筛选、诗人视图、诗词分布等交互；同时处理空数据情况。
6. 统一其他前台页面，检查路由、来源展示、键盘操作、图片加载及性能。

在内容基本齐备、生图能力可用、保留当前后端与 AI 功能、以四类重点页面为首期的前提下，粗估约 **8–15 人日**：设计及单页验证 1–2、人机协作素材制作与校核 2–4、公共样式与四页实现 3–5、响应式及回归 2–4。工作可并行；这是范围估算，不是交付承诺。全站其他页面、历史内容补证、正式情感分析不包含在内。

## 验收要点

- 在 1440、1024、768、390px 宽度检查；桌面双栏转为移动端上下结构，保留清晰的内容顺序。
- 六景卡随宽度转为三列、两列或单列，不将整张参考图等比例缩小。
- 文字、地名、按钮和图表均为真实页面内容；插画不含需要后续更新的文字。
- 同页插画的纸色、浓淡、笔触、人物年龄设定和景观比例一致；不可出现明显矩形贴纸边缘。
- 情感图显示统计方法和样本量，空朝代/缺失标签有说明，不制造数据点。
- 原有详情跳转、筛选、AI、来源展示和教学入口保持可用。
- 新图保留母版，网页用 WebP/AVIF 与响应式尺寸；设置宽高减少布局跳动，非首屏懒加载。
- 建议首屏新增媒体控制在 1.5MB 左右，单页新增媒体总量不超过项目原有 3MB 预算；LCP < 2.5s 作为约定测试环境下的目标，需实测。
- 完成后运行展示前端构建、相关逻辑测试和浏览器回归；当前只提交评估文档，无需为此次文档新增测试。
