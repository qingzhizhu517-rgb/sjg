# 图片/视频素材补强与可视化提升方案

> 用户诉求：页面缺图片/视频素材，可视化效果弱。本方案先盘点、后分批，**生成类素材一律先报价确认再执行**（项目约定）。
> 现状实测（2026-08, sjg01）：
> - `cultural_item` **63/63 全部无图**（含九城五类新增 44 条）→ 五类列表/详情/每城文化页纯文字，是"视觉弱"的最大来源
> - `poet` 头像缺 112、水墨头像缺 129（几乎全缺）
> - `scenic_spot` 缺图 22、水墨图仅缺 1（基本齐）、**缺视频 53**
> - `poem` 缺视频 168/203
> - 本地已有素材：hero 视频×2、timeline 场景图 9 张、real 景点图 3 张、crafts SVG 5 张——体量极小
> - 素材基建：`display-v2/public/media/{real,inkwash}/` 双风格同构路径 + `.workbuddy/skills/sjg-media-assets/SKILL.md`（AI 生成→裁水印→压缩→双风格→导 poster 的既定管线）；`useImage.js` 已有空值兜底雏形

## 总原则

1. **双主题同构**：每个实体配 real + inkwash 双图，路径沿用 `media/{real,inkwash}/...`（与未来 OSS 迁移同构，切换零改码）。
2. **成本分级**：P0 零成本程序化 → P1 AI 图片（低成本）→ P2 视频 → P3 音频（高成本）；生成前逐批报价。
3. **无图也有面子**：先做「程序化水墨纹样占位」，保证任何数据缺图时页面依然有视觉，而不是灰块。
4. 素材回填一律走 V23+ 幂等 migration（沿用 V18–V22 风格），不直改库。

## P0｜零成本 · 程序化视觉占位（纯代码，立即做）

目标：不生成任何素材，先让文化板块"有面子"。

1. **水墨纹样卡生成器**（新组件 `InkPatternCard.vue` 或 `useInkPattern.js`）：按条目 id/category 确定性生成 SVG 纹样（五类各一套：节=灯笼纹、诗=书卷纹、艺=刀凿纹、文=卷云纹、味=鼎食纹），配色走主题 token（米白底+朱红印章+细线）。
2. **列表卡图文结构升级**：FestivalList/FoodOperaList/LiteratureList 卡片改为「左图区（有图显图，无图显纹样）+ 右文字」，五类印章字复用。
3. **CityCulture 五格册页**：每格头部加纹样/图块（当前纯列表文字）。
4. **CulturalDetail**：加头图区（有图显图，无图纹样 + 印章）。
5. **素材采购清单**：生成 `docs/media-wishlist.md`（表×主题×数量×优先级×预估档位），作为 P1–P3 的报价依据。

验收：双主题下无裸灰块；上述页面均有纹样/图片视觉；build + test:unit 全过。

## P1｜低成本 · AI 图片素材（需确认成本后执行）

| 目标 | 数量 | 说明 |
|---|---|---|
| 文化条目图 | **MVP 45 城×类各 1 张 ×2 风格 = 90 张**（全量 63×2=126 张为后续批） | 每城每类先 1 张锚点图，同城同类条目复用；风格：real=实景质感插画，inkwash=水墨 |
| 诗人头像 | 先 top 40 高频展示诗人 ×2 风格 = 80 张 | 按诗人详情页/图谱访问频次排序；inkwash 优先（主力主题） |
| 景点补图 | 22 张 real（anime 仅缺 1 补齐） | 九城核心景点优先 |

流程（每条都走 SKILL.md）：AI 生图 → 裁水印 → ffmpeg/工具压缩（目标 ≤200KB/张）→ 双风格各一 → 命名 `spots/xx.jpg`、`poets/xx.jpg`、`culture/{category}/xx.jpg` 同构路径 → `V23__media_backfill.sql` 回填 `image_url`/`image_anime_url`/`avatar_*`。
生成前输出明细清单 + 积分报价，**确认后再批量**；失败条目记录重试。
