# display-v2 画卷展陈与高质量素材优先设计

**日期：** 2026-08-21

**状态：** 已确认设计方向，待用户审阅书面规格后进入实施计划

**主要范围：** `display-v2`、媒体数据库迁移；管理端和数据大屏仅处理本轮直接暴露的视觉一致性问题

## 1. 背景与目标

项目已经生成并纳入前端 20 张高质量水墨素材，源文件归档在：

`/mnt/e/Aohs/vibecoding/sjg-new-archive-20260821/legacy-output/img/`

这些文件与 `display-v2/public/images/{poets,spots,cultural}/` 中的 PNG 逐字节一致，并已有同尺寸 WebP 版本。当前问题不是素材缺失，而是展示策略没有发挥素材质量：

- 首页将 1600×900 的节气图铺满整个视口，`object-fit: cover` 在大屏上放大并裁切，细节显得松散、模糊。
- 24 张节气图一次只露出一张，其余素材被压缩成右侧细刻度；移动端甚至隐藏节气名称，无法形成“多素材展陈”的感受。
- 诗词详情把标题、正文和注解强制竖排，长诗需要横向滚动，阅读成本高。
- `useImage.getImageUrl()` 会把 `.png` 强制改写为 `.jpg`，并继续推导 `_anime.jpg`，导致已经存在的高质量 PNG/WebP 静默回退到占位图。
- 时间轴小舟源文件是 RGB WebP，棋盘格已经烘焙进像素，并不是真透明背景；组件又把 1024×942 的图片强制压成 60×60。
- 时间轴场景图覆盖整张长卷并裁切，容易和朝代节点、河流路径争夺视觉焦点。
- `RiverHero.vue` 样式中存在一个多余的右花括号，虽然当前构建器容错通过，但属于应清理的样式隐患。

本轮目标：

1. 把首页从“全屏轮播背景”改成可浏览的“二十四节气画卷展陈”。
2. 让横幅、竖幅、方形素材按原始构图进入合适版式，而不是统一裁成背景图。
3. 将诗词正文改成默认横排诗笺，优先保证阅读体验。
4. 建立确定的水墨素材优先级，让数据库中的高质量媒体稳定命中 WebP。
5. 输出真正带 alpha 通道的小舟素材，并收敛时间轴场景层。
6. 保持现有单一水墨主题、路由、API 返回结构和业务功能不变。

## 2. 已评估的视觉路线

### 路线 A：强化现有沉浸全屏

继续使用全屏背景，只增加焦点裁切、预加载和更好的遮罩。改动最小，但 1600×900 素材仍会在高分辨率屏幕上被放大，24 张图仍缺乏同时可见的展陈感。

### 路线 B：画卷展陈（采用）

把图片限制在有边界的纸本画框内，以 `contain` 或按素材类别配置的安全裁切展示；同时提供可见的节气缩略图带和展签信息。该路线最符合水墨素材本身已有题字、留白和印章的构图，也最能解决画质感知与多素材发现性问题。

### 路线 C：现代博物馆栅格

使用更现代的白盒展厅与规整卡片栅格。可读性高，但会削弱项目已经形成的水墨叙事识别度，并需要更大范围重做全站设计系统。

## 3. 首页：二十四节气画卷展陈

### 3.1 桌面布局

`RiverHero.vue` 保留为首页入口，但从全屏背景组件改为容器内的双栏展陈：

- 外层仍使用暖纸色与轻微纤维纹理，但不再把节气图铺满视口。
- 内容最大宽度沿用 `--container-max`，桌面端首屏最小高度设为 720px，不强制图片占满整个屏幕。
- 左栏约占 68%，放置当前节气主画卷：
  - 固定 16:9 展示区；源图为 1600×900，正常只缩小不放大。
  - 图片使用 `object-fit: contain`，保留题字、印章和原始留白。
  - 画卷外围使用窄纸边、墨色细线和克制阴影，不使用厚重圆角卡片。
  - 当前节气、地点和序号以展签方式放在画框下方，不压在图片主体上。
- 右栏约占 32%，承载项目标题、简介、实时统计和节气说明：
  - 标题层级保持清晰，但字号从全屏海报尺度收敛到展厅标题尺度。
  - 当前节气说明与轮播控制放在同一区域。
  - 自动轮播默认保留，间隔 8 秒；用户点击、悬停画廊、聚焦控件或页面失去可见性时暂停，避免阅读时被强制切换。

### 3.2 二十四节气素材带

主画卷下方增加明确可发现的节气缩略带：

- 桌面端展示 6 个相邻节气缩略图（当前项、前两项、后三项），当前项更宽并显示完整名称，其余显示缩略图、序号和短名称。
- 前后项根据当前节气循环计算，不一次解码全部大图；当前、前一张、后一张优先预取。
- 用户可点击缩略图、上一项、下一项和播放/暂停按钮切换。
- 使用真实按钮与可见焦点环，保留 `aria-current`，键盘左右方向键可切换。
- 不再使用只有 1px 宽、默认隐藏名称的 24 项竖刻度轨。

### 3.3 移动端

- 主画卷保持 16:9，不使用全屏高度。
- 右栏内容移动到画卷下方。
- 24 节气改为可横向滚动的命名缩略条，滚动条或边缘渐隐必须提示仍有更多内容。
- 统计信息使用 2×2 栅格；标题、说明和控件保持最少 44px 点击区域。
- `prefers-reduced-motion` 下关闭交叉淡入和自动播放。

## 4. 高质量素材的页面分工

### 4.1 横幅景点与节庆图

1672×941 横幅素材用于景点详情主画卷、文化详情横幅和精选内容带。默认策略：

- 详情主视觉使用 `contain`，避免裁掉图片左侧题字或右侧建筑主体。
- 小卡片允许 `cover`，但 20 张精选素材必须进入单独的媒体展示配置表，逐张声明 `aspectRatio` 和 `objectPosition`；未配置的精选素材回退 `contain`，不能统一按居中裁切。
- 泰山 941×1672 竖幅例外，进入竖向展签或双栏详情，不裁成横幅。

### 4.2 诗人竖幅

1086×1448 诗人图用于人物列表、人物详情和首页精选诗人：

- 列表卡片采用 3:4 或 4:5 肖像框。
- 详情页采用完整竖幅展签，优先 `contain` 或轻度底部裁切，保留人物、题字和桌面器物。
- 不把诗人竖幅当作横向背景图。

### 4.3 方形文化图

1254×1254 的甏肉干饭、曹州面塑、鲁锦织造进入 1:1 文化卡片；横幅的牡丹节与祭孔大典进入 16:9 展签。文化列表根据素材比例选择卡片模板，不再用同一个固定裁切比例处理所有类别。

### 4.4 WebP 优先

运行时优先使用现有 WebP：视觉尺寸不变，但单图由约 2.4–3.5MB 降到约 0.16–0.54MB。PNG 继续保留为高质量源文件和兼容回退，不在页面默认请求中使用。

## 5. 统一图片解析与数据库回填

### 5.1 前端解析规则

重构 `display-v2/src/composables/useImage.js`，停止无条件 `.png → .jpg` 改写。候选顺序固定为：

1. 数据库给出的精确路径对应的同名 `.webp`（存在时）。
2. 数据库给出的精确路径。
3. 仅在调用方明确要求水墨候选、且原路径没有 `_anime` 时，尝试同目录同 basename 的 `_anime.webp`、`_anime.png`、`_anime.jpg`。
4. 最后才返回语义化印章占位图。

路径推导拆成纯函数，避免 `import.meta.glob` 使单元测试无法运行。页面组件统一通过 `resolveImage` 或新的实体媒体适配器取图，逐步停止直接消费互相矛盾的 `imageUrl/imageAnimeUrl` 顺序。

### 5.2 数据库迁移

新增 `V26__preferred_inkwash_media_paths.sql`：

- 对 10 位诗人、5 个景点、5 条文化项目做精确 `id/name/title` 校验。
- 将相应 `avatar_anime_url` / `image_anime_url` 规范为 `/images/...webp`。
- 允许纠正旧的占位值或 PNG 路径，因此不是“仅空值填充”；但只触及这 20 个已经人工确认的实体和对应水墨字段，不覆盖 real 字段。
- 重复执行时写入相同值，结果幂等。
- 不直接连接或修改线上数据库；提交 migration，由现有 `scripts/apply_migration.py` 在用户指定环境应用。

## 6. 诗词详情：横排诗笺

### 6.1 组件边界

从当前 500 余行的 `PoemDetail.vue` 中抽出 `components/poem/PoemManuscript.vue`，只负责诗笺主视觉。页面继续负责 API 加载、错误状态、AI 赏析、创作背景和视频。

### 6.2 排版

- 标题横向居中，朝代与作者在标题下形成一行展签；作者和景点保留可点击链接。
- 正文默认横排，最大阅读宽度约 30em，桌面字号约 22–24px，行高 2–2.2。
- 每句独立成行；原数据有换行时尊重换行，只有单段长字符串时按 `。！？；` 保留标点切句。
- 绝句、律诗保持紧凑居中；长诗允许更宽的段间距和自然纵向延展，不产生横向滚动区。
- 注解改为横排折叠区，位于正文下方或桌面右侧窄栏；不再使用竖排注解。
- 情绪标签、印章和纸张纹理保留，但装饰不得压过正文。
- 背景意境图只作为低对比度局部水印或边缘墨晕，不再铺成高对比度页面背景。

### 6.3 可访问性与响应式

- 正文是正常文档流，浏览器选择、复制和屏幕阅读顺序与视觉顺序一致。
- 移动端字号约 18–20px，左右内边距 20px，不出现横向滚动。
- 动画只做 200–400ms 的轻微淡入；减少动态偏好下完全关闭逐句动画。

## 7. 时间轴与透明小舟

### 7.1 小舟素材处理

当前 `boat-rower.webp` 为 1024×942 RGB，棋盘格是实际像素。实施时生成新的透明 WebP：

- 以浅色、低饱和棋盘格为背景类别建立 alpha mask。
- 保留船体和人物深色墨迹，并允许边缘浅墨形成半透明过渡。
- 裁掉大面积空白后保留安全边距。
- 输出 WebP RGBA；透明像素须占画布至少 15%，alpha 大于 16 的主体像素须占至少 10%，裁切后主体包围盒与画布四边的安全边距控制在 4–16px。
- 原文件在 Git 历史和工作区外归档中可恢复，不修改归档源文件。

组件中小舟使用 `width: clamp(82px, 7vw, 120px); height: auto`，不再压成正方形；拖拽命中区通过外层透明按钮或伪元素扩大，不靠放大棋盘底图。

### 7.2 时间轴场景层

- 朝代场景图限制在长卷画面区，以 `contain` 和柔和边缘遮罩呈现，避免 3:1 容器对原图大幅裁切。
- 场景不再覆盖信息面板；河流路径和朝代印章保持最高信息层级。
- 当前与相邻场景的懒加载策略保留。
- 自动巡航、拖拽和键盘朝代切换行为不变。

## 8. 管理端与数据大屏边界

本轮不重构 `admin-frontend` 或 `sjg-datav`。只在最终联调发现以下直接问题时做小修：

- 管理端媒体预览因新 WebP 路径无法显示。
- 数据大屏读取规范化媒体路径后出现破图，或主体被裁掉超过其原始包围盒的 20%。
- 共享的图片字段优先级与展示端冲突。

除此之外的视觉升级进入后续独立任务，避免本轮范围失控。

## 9. 错误处理与降级

- 任一节气图片加载失败时保持纸色画框，并显示节气名称展签；不得整块空白或闪黑。
- 图片解析失败时显示类别正确的印章占位，不回退到无关人物图。
- WebP 不可用时回退同名 PNG/JPG。
- 数据库 migration 未应用时，前端仍能消费现有 PNG 路径；迁移应用后自动优先 WebP。
- 小舟透明素材加载失败时保留可聚焦的文本替代按钮，时间轴节点切换仍可操作。

## 10. 验证标准

### 自动验证

- `display-v2` 新增诗句切分、节气相邻项计算、图片候选顺序的纯函数单元测试。
- `npm run test:unit` 全部通过。
- `npm run build` 通过。
- `admin-frontend` 与 `sjg-datav` 若有修改，各自构建通过。
- 后端 `mvn test` 通过；V26 通过 `git diff --check` 和 SQL 静态审查。
- 小舟资产验证：WebP 为 RGBA；透明像素占比 ≥15%，alpha 大于 16 的主体像素占比 ≥10%，主体四周安全边距为 4–16px，文件体积 ≤300KB。

### 视觉验收

- 1440×900、1920×1080：节气主图不被放大到超过源尺寸，题字和主体完整可见。
- 390×844、768×1024：没有横向页面滚动；节气缩略条可发现、可操作。
- 首页无需等待轮播即可看到多张节气素材。
- 诗词详情正文横排，无横向滚动；短诗与长诗都可自然阅读。
- 20 张高质量素材优先命中 WebP，页面不再静默显示占位印章。
- 小舟周围无白色或棋盘格矩形，宽高比正确。
- 键盘焦点、减少动态偏好和错误降级可用。
