# 齐鲁名士详情页 B-1 桌面重设计

**日期：** 2026-08-24  
**状态：** B-1 视觉方向已确认，书面规格待用户复核  
**范围：** `display-v2` 齐鲁名士详情页；本阶段只验收桌面 Web，不改移动端布局策略

## 1. 背景与目标

当前齐鲁名士详情页的头像框只有 240×320px，头像角落叠加朝代方印，首屏又以“代表作”大卡抢占视觉焦点；生平内容被 `max-width: var(--measure)` 和卡片内边距限制成窄栏。高质量人物 WebP 素材实际为约 1086×1448px 的 3:4 竖幅，素材本身足以支持更大展示。

本次重设计的目标是把页面焦点重新排序为：

1. 人物画像与人物档案；
2. 可舒适阅读的完整生平；
3. 轻量、可进入详情的代表句；
4. 传世诗篇集合。

页面继续使用项目现有的宣纸、淡墨、朱砂主题 token，不引入新的主题、字体网络依赖或移动端改版。

## 2. 已确认的视觉方案：B-1 左图右淡

### 2.1 Hero 构图

- Hero 使用桌面编辑式横幅构图，目标容器宽度沿用 `--container-max`（当前为 1280px）。
- 人物画像置于左侧，占 Hero 视觉宽度约 55%–64%；右侧边缘以宣纸色渐变淡出，不能出现硬直切分界线。
- 画像使用完整 3:4 精选 WebP，默认 `object-fit: contain`，保留题字、人物和器物的原始构图；不做全屏放大，不以 `cover` 强行裁掉主体。
- 桌面画像展示区目标高度约 440–500px，宽度随容器变化，但不得压缩成当前 240px 小框。
- 画像层只承担氛围和人物识别，不叠加朝代方印；删除 `.pd-portrait__seal` 的模板与样式。
- 右侧信息层置于渐变之后的清晰宣纸区域，包含：唯一朝代题签、姓名、字号/别号、出生—去世年份、籍贯、职业或身份简介。
- 朝代信息只保留一次。朝代跨度作为题签的辅助文字（如数据可用）或不显示，不再作为人物统计卡。

### 2.2 信息层级与顺序

模板主结构调整为：

```text
返回名士
Hero（左侧画像渐隐 → 右侧人物档案）
生平（横跨主体宽度的编辑式阅读区）
代表句（轻量链接，引向对应诗词详情）
传世诗篇（卡片网格）
```

- “代表作”不再作为首屏大卡标题。当前接口没有权威 `representativePoemId` 字段，`pickSignaturePoem` 是启发式选择，因此展示文案统一改为“代表句”。
- 代表句保留诗句和作品名，但降级为无厚重阴影的横向引用条；整个条目应为可聚焦、可点击的 `router-link`，目标为 `/poems/{signature.id}`。
- 生平区块不再受窄卡 `max-width: var(--measure)` 限制。标题/题签可在左侧，正文放在右侧舒适阅读列；外层横跨主容器，正文阅读宽度控制在约 42–48em，避免一行过长。
- 诗篇网格继续复用现有路由卡片和空态逻辑，位于页面底部，不与人物 Hero 争夺首屏主视觉。

### 2.3 视觉语言

- 背景、文字、边框、朱砂强调全部使用 `variables.css` 中已有 token；不新增硬编码黑白或第二强调色。
- 结构分组以留白、细线和层级排版完成，减少嵌套卡片与厚重阴影。
- Hero 画像淡出采用单向线性渐变，过渡区域必须覆盖足够宽度以保护右侧文字对比度；当图片加载失败时，渐变区域仍保留宣纸底和可识别的 `InkPlaceholder`。
- 动效只保留已有 reveal/hover 语义，时长控制在 100–300ms，并遵守 `prefers-reduced-motion`。

## 3. 组件与数据边界

### 3.1 `PoetDetail.vue`

页面继续负责 API 请求、加载/错误状态、路由返回地址和诗篇列表。模板重排与 scoped CSS 改造集中在该文件，避免本次任务扩散到全局主题。

建议新增或调整的局部派生状态：

- `avatarLoadFailed`：头像请求失败时切换到 `InkPlaceholder`，不能只把 `<img>` 隐藏后留下空框。
- `avatar` 继续遵循 `avatarAnimeUrl` 优先、`avatarUrl` 兜底；`getCuratedPresentation` 保持 3:4/contain 配置。
- `signature` 继续复用共享 `pickSignaturePoem`，但只作为代表句数据源；无诗篇时不渲染代表句。

### 3.2 不在本次范围内的接口改动

- 不新增或修改后端字段，不执行数据库迁移。
- 不把启发式 `pickSignaturePoem` 冒充为权威代表作数据；若未来需要人工指定代表作，另立数据模型任务。
- 不改 `/poets/:id` API 的返回结构。
- 不改移动端现有断点布局；本轮只保证桌面断点（大于 1024px）的 B-1 视觉和行为。现有移动端 CSS 作为后续任务单独评估。

## 4. 错误处理与可访问性

- 图片加载失败、无图片、WebP 不可用时均显示 `InkPlaceholder`，并保留人物名称的替代文本。
- 装饰性水印、细线和图标不进入屏幕阅读器名称；朝代只被朗读一次。
- 代表句使用真实链接，键盘焦点状态与诗篇卡一致；诗篇卡的“阅读全文”在键盘聚焦时也应保持可见或有等价焦点反馈。
- 生平缺失时保留现有兜底文案“生平待考，然其诗已传。”，不显示空白卡片。
- 数据加载错误继续使用现有 `ErrorState` 和重试入口。

## 5. 测试与验收

### 5.1 自动测试

新增源码/结构测试覆盖：

- 桌面画像宽度达到至少 360px 的 B-1 规格，且保留 `3 / 4` 与 `contain` 展示配置。
- 模板不再包含 `.pd-portrait__seal`，页面只保留一个朝代题签。
- 主要标题顺序为“生平 → 代表句 → 传世诗篇”。
- 代表句为 `/poems/${signature.id}` 链接，且无诗篇时不渲染。
- 头像加载错误能切换到 `InkPlaceholder`。
- 生平正文不再使用窄列 `max-width: var(--measure)`。

保留并通过现有 `display-v2` 单元测试；不修改与本页无关的工作区改动。

### 5.2 桌面视觉验收

- 在 1440×900 和 1920×1080 浏览器宽度下，Hero 保持左图右淡双层关系，画像与右侧文字不重叠。
- 画像主体完整可辨，右缘渐变自然，右侧姓名/简介对比度足够。
- 生平横跨主体宽度，正文单行不超过舒适阅读长度，右侧不出现大块空白。
- 代表句视觉权重明显低于 Hero 与生平，但仍可发现和点击。
- 诗篇网格位于下方，保留现有 hover、键盘焦点和空态。
- 本阶段不以移动端断点作为验收条件；不得因桌面改造引入页面级横向溢出。
