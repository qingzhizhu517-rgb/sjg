# 展示前端统一即时回顶设计

**日期：** 2026-08-25
**状态：** 用户已确认设计方向，待实现前复核
**范围：** `display-v2` 路由导航滚动行为

## 1. 背景与目标

从诗人列表进入诗人详情时，页面偶尔停留在原列表的中下部，而不是详情页顶部。排查显示，路由的顶部定位与全局 `html { scroll-behavior: smooth; }`、详情页异步数据加载及 GSAP 入场刷新同时发生，形成滚动竞态。相同路由机制也覆盖诗词、景点和四类文化详情页，因此不能只在诗人页打补丁。

目标是建立一套可预测的全局规则：进入新页面立即回到顶部，浏览器历史导航恢复用户离开列表时的位置，列表内筛选和标签切换不被路由系统强行拉回顶部。

## 2. 交互规则

| 导航情形 | 期望行为 | 说明 |
| --- | --- | --- |
| 首次进入应用 | 顶部（`left: 0, top: 0`） | 不继承浏览器旧页面位置 |
| `to.path !== from.path` 的新页面导航 | 立即回顶 | 覆盖列表→详情、详情→详情、城市/地区→列表等导航 |
| 浏览器前进/后退且存在 `savedPosition` | 恢复保存的位置 | 不做平滑动画，避免与页面异步渲染竞争 |
| 同一路径仅 query/hash 变化 | 保留当前位置 | 由页面自身在需要时显式滚动到结果区或锚点 |
| 页面内按钮主动滚动 | 维持调用方指定的行为 | 例如结果区使用 `scrollIntoView({ behavior: 'smooth' })`，不受路由策略替换 |

### 覆盖的详情入口

- `/poets/:id`
- `/poems/:id`
- `/spots/:id`
- `/festivals/:id`
- `/crafts/:id`
- `/literature/:id`
- `/food-opera/:id`

地区、城市、时间轴及文化列表之间的跨路径导航也遵循同一规则；查询参数筛选仅在路径不变时保留位置。

## 3. 实现边界

1. 新增一个无 DOM 的纯函数模块（建议 `src/utils/routeScroll.js`），集中计算路由滚动决策。
2. `src/router/index.js` 的 `scrollBehavior` 只负责把 Vue Router 参数传给该纯函数，避免页面组件各自处理回顶。
3. 删除 `src/styles/variables.css` 对 `html` 的全局 `scroll-behavior: smooth`；页面内需要平滑效果的调用点保留显式 `behavior: 'smooth'`。
4. 不修改详情页数据接口、组件生命周期、过渡模式或移动端布局。
5. 不改变浏览器历史栈，也不把 query 变化改成新的 push/replace 语义。

## 4. 测试与验收

### 自动回归

使用现有 Node 内置 `node:test`：

- `savedPosition` 原样返回，确认前进/后退可恢复位置；
- 路径变化返回 `{ left: 0, top: 0 }`，确认新详情和其他新页面即时回顶；
- 同路径 query/hash 变化返回 `false`（或等价的保留当前位置结果）；
- 首次导航（无来源路由）返回顶部；
- 读取 `variables.css` 的全局 `html` 规则，确认不再声明 `scroll-behavior: smooth`。

### 桌面浏览器验收

在展示前端开发服务器中逐项验证：

1. 将 `/poets` 列表滚到中下部，打开任一诗人详情；路由切换后以及详情数据加载完成后，`scrollY` 均为 `0`。
2. 对 `/poems`（由景点诗词入口进入）、`/spots/:id`、节庆、工艺、文学、饮食戏曲详情重复第 1 项，确认没有同类残留。
3. 从详情返回列表，确认浏览器后退恢复原列表滚动位置。
4. 在诗人、时间轴及文化列表切换 query 筛选/标签，确认当前位置不被重置；页面需要定位结果时仍能执行自己的显式滚动。

## 5. 提交边界

本设计及后续实现使用独立提交。实现只涉及路由滚动纯函数、路由接线、全局滚动样式和对应测试；保留工作区其他用户改动，不修改后端或数据库。
