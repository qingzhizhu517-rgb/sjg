## 0. 背景与定位

### 0.1 项目定位(本轮已锁定)

**齐鲁文化扩容**: 诗词为**核心载体**, 民俗 / 非遗 / 景点 / 民间文学等并置; **黄河作山东段意象**(非全局主题, 但作首页地图的视觉与叙事主轴); #8 拓展栏目为**正式栏目**, 非远景。

此定位同时约束 #1 诗人范围(齐鲁口径不变)、#3 首页黄河定位(山东段意象)、#8 拓展口径(并置多文化形式)。

## 2. 逐项需求

### #1 诗人信息: 分层展示 + 完整度治理

- **现状**: 126 诗人, 37%-100% 各字段缺失; 74% 仅 1 首; 先秦空朝代; 信息薄而非"诗少"; 水墨头像 100% 缺。
- **目标**: 全量保留不删, 按完整度分层展示, 让平台"不空洞又不裸奔"。
- **核心决策**:
  - **分层展示**(非软隐藏、非硬删除): 高完整度 → 大卡 / 推荐位(本期名士·传世最丰 ~9 位); 中 → 名士卡墙常规位; 低 → 折叠进"更多 / 全量"末位(默认收起)。
  - **完整度分**(0-100, 后端算好随 poet 返回):
    `bio(20) + real_avatar(15) + ink_avatar(15) + style(15) + birthplace(10) + birth_year(10) + poem_count_norm(15, ≥3 满分)`
    分层阈值: ≥70 精品 / 40-69 常规 / <40 折叠。
  - **并行补全工作线**: 水墨头像 AI 生成(126 位, 见 #2 素材); 传记 / 风格 / 生年优先补精品层。
  - 先秦空朝代 tab 在朝代 rail 中隐藏(数据为 0 不展示)。
- **依赖**: #2 design token / 双主题(头像兜底); 素材补全长线。
- **优先级**: **P0**。
- **待定**: 完整度分权重是否需调; 低完整度"折叠"默认展开还是收起(建议默认收起 + "展开全部"按钮)。
- **验收**: 朝代 rail 无空 tab; 名士页分层生效; 完整度分随 API 返回; 坏文件名已清洗。

### #2 前端整体美观与布局

- **现状**: 纸本水墨·杂志式语言已锁定; 双主题 real/inkwash 不一致(水墨头像 100% 缺是症状); 素材家底薄(音频 0 / 水墨头像 0 / 真人头像缺 109 / 视频缺 160)。
- **目标**: 在已锁语言内收口双主题、补精致度、理信息架构, 素材分类型补齐。
- **核心决策**:
  - **精致度打磨**: 进场 / 滚动动效节奏、间距与字号层级、卡片与分区一致性、空状态 / 加载态。低风险渐进。
  - **双主题收口**: 抽统一 design token(CSS 变量已部分存在, 补齐); 补 inkwash 资产(与 #1 头像补全合流); 换主题不破版。
  - **信息架构与导航**: 重排三主页(山河图志 / 齐鲁名士 / 文脉长河)结构; #8 民俗进导航(本轮先占位); 首页到详情跳转 / 返回动线顺。
  - **素材分类型混搭**(缺口填充策略):
    - 诗人头像 / 插图 → AI 生成(水墨统一风格 + 人工筛), 与 #1 合流。
    - 朗读音频 → TTS 生成(195 首)。
    - 诗词视频缺口(160) → 图片 + Ken Burns 动效替代, 不强求真视频。
    - 事件图 → 占位兜底。
  - **数据清洗**: OSS 路径校验 + 坏文件名修复(`.jpg.jpg` / `.jpg.mp4`)。
- **依赖**: #1 头像补全; OSS(OssService)。
- **优先级**: **P0**(design token + 启动素材补全长线) / **P1**(精致度 + 导航)。
- **待定**: TTS 引擎选型(DeepSeek 无 TTS, 需另选如阿里 / 火山 / edge-tts); DataV-Vue3 是否引入(见 #6); 占位图风格规范。
- **验收**: 双主题切换不破版; 空态 / 加载态齐全; 导航含民俗占位; 坏文件名 0。

### #3 首页黄河意境(首页 = MapView, 不新写页)

- **现状**: 首页 `/` → `/map` = MapView(`Hero + 3D 地图 + 推荐位 + 数据看板`), 本分支 `feat/map-frame-layout` 正做 3D 地图框体化(左图右册 + 城市卡)。
- **目标**: 在现有 Three.js 地图场景里加黄河流光, 突出"山河图志"的"河", 强化山东段意象。
- **核心决策**:
  - **地图上叠黄河流光**: Three.js 沿黄河真实地理坐标(济南 / 泰安北 / 淄博北 / 滨州 / 东营入海)画流光河(Shader / TubeGeometry + 流动 UV), 沿河点亮城市 / 景点, 点河联动右侧城市卡。借 display-v3 `RiverPath` 思路(非代码复用)。
  - 不改首页主角(地图仍为主), 不新增页面。
  - 后期可挂 #8 民俗(沿河节点)。
- **依赖**: 当前地图框体化分支; #2 design token。
- **优先级**: **P1**(顺势当前分支)。
- **待定**: 黄河路径坐标精度(需一份山东段黄河折线数据); 流光视觉强度与性能(字符多 / 移动端是否降级)。
- **验收**: 地图可见流动黄河; 沿河城市可交互联动右侧卡; 桌面性能稳定。

### #4 诗词页 AI 分析(PoemDetail)

- **现状**: PoemDetail 展诗 + `sentimentTags`; 全局 AI小文 = `AiChatBox.vue`(DeepSeek+RAG+SSE)。
- **目标**: 诗词页内嵌结构化 AI 赏析, 与全局小文分工(页内赏析 vs 全局问答)。
- **核心决策**:
  - **页内 AI 赏析卡**(非对话): 结构化输出 逐句解读 + 情感 + 创作背景 + 字词注解。
  - 走专门 prompt, 复用 `ChatService` / `LlmClient`; **进页预生成 + 缓存**(避免每次访问实时调 LLM)。
  - 与全局 AI小文 区分定位, 不互斥。
- **依赖**: AI 后端(ChatService); #2 卡片样式。
- **优先级**: **P2**。
- **待定**: 缓存表设计(`poem_analysis`?); 缓存失效策略(诗内容变更才刷); 赏析卡是否含"追问小文"入口(本轮先不含, 留双轨余地)。
- **验收**: 进诗词页有结构化赏析卡; 首次生成后走缓存; 与小文不冲突。

### #5 AI 写诗渲染模块

- **现状**: 无。用户期望"一笔一画写出诗"。
- **目标**: 诗以逐字落墨动效"写"出, 配水墨意境。
- **核心决策**:
  - **逐字落墨渲染**(不做真笔顺): 每字水墨晕染 + mask 按方向揭示(CSS mask / clip-path + GSAP stagger), 避开笔顺字形数据依赖; 与水墨调性更合(HanziWriter 笔顺动画偏"干净数字", 与纸本水墨不符, 故不采用)。
  - **诗源先精选起步**: 从现有 195 首精选经典 + AI 配题跋 / 赏析; **AI 自写为后续可选**(LLM 古诗质量不稳, 避免首页翻车)。
  - 预生成 + 前端播放动画。
- **依赖**: #2 样式; GSAP; 诗源数据。
- **优先级**: **P2**。
- **待定**: 模块位置(独立"即兴赋诗"页 / 首页 hero 动画 / 诗详情页装饰, 三选一, 本轮待定); 是否做多首轮播。
- **验收**: 选定诗可逐字落墨写出; 动效流畅; 桌面 / 移动降级合理。

### #6 数字化可视面板

- **现状**: echarts + g6 已装; 数据可讲故事(朝代 / 情感 / 景点地理 / 时间线 / 黄河城市)。
- **目标**: 站内公开数字看板页, 现代大屏观感。
- **核心决策**:
  - **站内 `/dashboard` 看板页**(新增路由, 非展厅大屏): 复用 echarts + g6, 参考 **DataV-Vue3** 视觉风格(仅参考, 不强引重框架; 视情况引其轻量组件)。
  - 内容: 朝代分布、诗词情感(sentimentTags)分布、景点地理密度、时间线诗词量、黄河流经城市文化密度。
- **依赖**: #1 数据治理(看板数据干净); #2 design token。
- **优先级**: **P2**。
- **待定**: 是否引 DataV-Vue3(license / 体积); 是否需移动端适配(看板通常桌面); 数据刷新频率(静态快照 vs 实时)。
- **验收**: /dashboard 可访问; 各图正确渲染; 视觉现代统一。

### #7 关系图谱优化升级(v2 先做出来)

- **现状**: v2 未实现; schema 无诗人-诗人关系表, 仅能派生弱关系。
- **目标**: 先在 v2 把图谱做出来 + 一次到位, 再谈后续优化。
- **核心决策**:
  - **边从哪来**: 派生(同朝代 / 同景点题诗 / 同籍贯)作底 + **补关键关系**(李杜 / 苏黄 / 齐鲁并称等, 人工或 AI 辅助录入)。
  - **G6 v5 力导向图**; 先 **诗人-诗人**, 后扩为 诗人-诗-景点-事件 知识图谱。
  - 完成 PoetList 的 关系图谱 tab(当前分支在途)。
- **依赖**: #2 样式; 新 `poet_relation` 表(见 §3)。
- **优先级**: **P1**(顺势 PoetList 在途)。
- **待定**: 关键关系种子清单(需与现有 126 诗人对齐, 候选: 李白-杜甫、苏轼-黄庭坚、李清照-赵明诚、济南二安等); 派生边阈值(同景点至少几首才算关联); 图节点过多时的折叠 / 筛选策略。
- **验收**: PoetList 关系图谱 tab 可用; 关键关系节点有文化味; 桌面性能稳定。

### #8 拓展业务(民俗等, 数据先行)

- **现状**: 仅诗词 + 景点。定位为齐鲁文化扩容, 拓展为正式栏目。
- **目标**: 本轮写入文档 + 数据模型 + 数据收集, 数据到位后挨个开发页面。
- **核心决策**:
  - **远景类目(全纳入, 分批做)**: 民俗节庆 / 非遗工艺 / 民间文学 / 饮食戏曲。
  - **本轮**: ① 设计统一 **culture 内容抽象**(见 §3); ② 定义 4 类目数据字段与采集来源; ③ 导航 / 黄河轴接入位预留; ④ 数据到位后按类目挨个开发页面。
  - 民俗节庆为首批(与齐鲁文化底色最合); 沿黄河民俗可挂 #3 流光河轴。
- **依赖**: #2 导航; #3 黄河轴; culture 抽象表。
- **优先级**: **P3**(数据先行)。
- **待定**: 各类目具体字段(非遗有工艺步骤 / 民俗有节令时序, 字段需差异化, 抽象表 + 类型扩展字段); 数据采集来源(官方非遗名录 / 文旅公开 / 人工录入)。
- **验收**: culture 抽象模型定稿; 至少 1 类目(民俗)数据采集完成并入库可展示。

## 5. 风险与待定清单

1. **水墨头像 100% 缺**: 不补则 inkwash 主题长期破版, 是 #2 / #1 的硬前置。AI 生成 126 位需统一风格 + 人工筛, 耗时。
2. **朗读音频 0**: TTS 引擎与质感待定, 195 首批量生成有成本。
3. **LLM 古诗质量**: #5 暂不上 AI 自写, 先精选起步。
4. **关系数据薄**: 无诗人-诗人关系表, 派生边"弱", 关键关系需人工 / AI 补并校验。
5. **OSS 路径 / 坏文件名**: 数据脏需清洗, 否则 #2 素材呈现崩。
6. **display-v3 / display-frontend 旧端**: 仅参考, 不收口; 若后续需收口需另起决策。
7. **TTS / 图像生成模型选型、DataV-Vue3 引入与否、#5 模块位置、poet_relation 种子清单** —— 均「待用户确认」, 列入各专项 spec 时决策。

## 6. 后续流程

本文为**路线图级**需求。真正开发某项时, 仍按: **专项设计 spec(走 brainstorming) → 实现计划(writing-plans) → 编码**。建议从 P0 的 #1(分层 + 数据清洗)与 #2(design token + 启动素材补全长线)先行, 因其为基础且与当前 `feat/map-frame-layout` 分支的在途工作(#7 / #3)可并行收尾。
