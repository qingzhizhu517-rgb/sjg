# display-v2 三页面杂志式改版设计

> 状态: 待用户审阅
> 日期: 2026-07-01
> 范围: display-v2 用户端三大主页面（山河图志 / 齐鲁名士 / 文脉长河）

## 背景与目标

用户反馈 display-v2 的用户端首页"内容空洞、排版单一、动画效果都没有"，且整体未达到"精致"水平。

本次改版以"保留中式水墨调性、打磨精致度"为前提，将三个主页面统一升级为"杂志式 Hero + 多区域 + 动效全开"的标准档结构，补足内容密度、排版层次、动效表现。

## 已锁定的设计决策

| 维度 | 决策 |
|---|---|
| 设计语言 | 保留 real / inkwash 双主题中式水墨调性 |
| 内容来源 | 后端数据 + 1–2 个编辑推荐位 |
| 动效 | 全开：进场 + 滚动揭示 + 微交互 + 环境氛围 |
| 排版 | 杂志式 Hero（A） |
| 档位 | 标准档：Hero 50% 屏高 + 专题区 + 卡片墙 |
| 动效技术 | GSAP + ScrollTrigger（新增依赖 `gsap@^3.12`） |

## 三、数据流

### 3.1 新增 composable `useHomepageData.js`

暴露三个 reactive 集合：

```
map:    { cities[], featuredSpots[], featuredPoems[], stats{} }
poets:  { list[], featured[], graphPreview, stats{} }
timeline: { dynasties[], featuredPerDynasty{}, stats{} }
```

策略：
- 并行请求：`Promise.allSettled([...])`
- 失败不阻塞：单页某一块失败时，其他块仍渲染（空态提示该块失败）
- 缓存：keep-alive 期间复用，无重复请求
- 字段映射：所有中文枚举（dynastyId → 唐代/宋代...）放在 composable 内部，组件不感知

### 3.2 API 列表

| 数据 | 端点 | 用途 |
|---|---|---|
| 地图统计 | `GET /stats/map` | 10 景点 / 6 大家 / 8 名篇 / 9 城市 |
| 推荐景点 | `GET /spots/featured?limit=2` | 山河图志右侧推荐位 |
| 9 城 | `GET /regions/along-yellow` | 山河图志底部九城卡片墙 |
| 名士列表 | `GET /poets?size=100` | 齐鲁名士墙（已有） |
| 名士统计 | `GET /stats/poets` | 4 朝 / 6 位 |
| 推荐名士 | `GET /poets/featured?limit=2` | 齐鲁名士推荐位 |
| 名句 | `GET /poems/featured?limit=1` | "今日名句" |
| 时间线 | `GET /timeline` | 朝代年轮（已有） |
| 时间线统计 | `GET /stats/timeline` | 8 朝 / 50+ 事件 |
| 同期推荐 | `GET /timeline/:dynasty/featured` | 右侧按朝代联动 |

> 后端如果缺少某些接口，需要协商补全或在前端 mock（mock 路径已存在 `src/config/mockDetailData.js`）。

## 四、动效（GSAP 细则）

| 动效 | 触发 | 实现 | 时长/缓动 |
|---|---|---|---|
| Hero 入场 | 路由进入 | `gsap.from` 标题/副标/CTA 错峰 | 0.8s · `power3.out`，stagger 0.12s |
| 滚动揭示 | 元素进入视口 15% | ScrollTrigger → `gsap.from` | 0.6s · `power2.out` |
| 数字翻牌 | StatTicker 进入视口 | `gsap.to(obj, {val, snap: 1, ...})` | 1.2s · `power1.inOut` |
| 卡片 hover | 鼠标移入 | CSS transition（不动 GSAP） | 0.25s |
| 环境动效 | 常驻 | `gsap.timeline({repeat:-1})` | 8s · `sine.inOut` |
| 路由切换 | `<transition>` | 已存在的 `page-slide` 不动 | 0.35s |
| 推荐位揭示 | 滚动 | 错峰 stagger | 0.5s · stagger 0.08s |

### 性能约束

- ScrollTrigger 实例在组件卸载时一律 `kill()`（避免内存泄漏，参考现有 `MapView.vue` 的 `cleanupThree`）
- 滚动事件用 `{ passive: true }`
- 移动端检测：`<768px` 时禁用 Hero 粒子、卡片 stagger 减半

## 五、错误处理

- **网络失败** → 卡片用占位骨架（纯 CSS shimmer），整页失败时显示错误态
- **部分失败** → 其他模块继续渲染，失败模块显示「数据加载失败，点击重试」
- **图片加载失败** → `onerror` 切到 `default-avatar.svg`
- **滚动揭示异常** → 降级为直接可见

## 七、验收标准（DoD）

- [ ] 三个页面都有 Hero（含 eyebrow / title / subtitle / StatTicker / CTA）
- [ ] 每个页面至少 2 个推荐位，后端数据填充
- [ ] 每个页面都有底部卡片墙（地图: 9 城 / 名士: 大卡 / 时间线: 跨朝代）
- [ ] Hero 入场有错峰动画；推荐位/卡片有滚动揭示
- [ ] StatTicker 数字进入视口时翻牌
- [ ] 卡片 hover 有上浮 + 描边
- [ ] 环境动效在三个页面都有（金粉/印泥/水流光带循环）
- [ ] real + inkwash 双主题下都美观
- [ ] `<768px` 移动端布局可用
- [ ] 路由切换、组件卸载无内存泄漏（无残留 ScrollTrigger 实例）
- [ ] 后端某接口失败时不影响其他模块渲染

## 八、风险与开放问题

- **后端接口是否齐全**：`/stats/map`、`/spots/featured`、`/regions/along-yellow`、`/stats/poets`、`/poets/featured`、`/poems/featured`、`/stats/timeline`、`/timeline/:dynasty/featured` 共 8 个可能需要后端补全。落地前需先盘点后端已实现接口。
- **GSAP 商业许可**：GSAP 3.x 起对绝大多数商业用途免费（具体以官网为准）。本项目为科研教学用途，无风险。
- **移动端动效降级**：需要在 HeroBanner / StatTicker 组件内做 `window.matchMedia` 检测。
- **3D 地图与 Hero 共存**：山河图志 Hero 50% 屏高 + 3D 地图主区，可能首屏内容拥挤。需要在真机验证 1080p / 1440p / 4K 下的视觉比例。
