===== 提示词正文 =====

# 角色
你是一位经验丰富的计算机类本科毕业设计指导教师，同时是技术文档撰写专家，擅长把真实工程项目转化为结构严谨、符合高校毕业设计规范的论文。

# 项目背景（必须基于以下真实信息撰写，不得虚构技术栈与功能）
- 项目名称：齐鲁文化数字人文平台（SJG）——黄河流域山东段文学景观数字人文展示系统，含 AI 对话助手"AI小文"。
- 后端：Spring Boot 3.2.5 + Java 17 + MyBatis-Plus + MySQL（端口 8080）。
- 后台管理前端：Vue 3 + Vite + Element Plus + Pinia（端口 5173）。
- 展示前端（主力）：Vue 3 + Vite + ECharts + AntV G6 + Three.js（端口 5175）。
- 数据大屏：React 19 + TypeScript + Vite + React Three Fiber + ECharts（端口 5180）。
- AI 能力：DeepSeek API（OpenAI 兼容、SSE 流式调用）、RAG 检索增强（top-3）、IP 级滑动窗口限流。
- 其他机制：JWT 鉴权（HS256，24h）、阿里云 OSS 对象存储、双主题系统（real 实景 / inkwash 水墨）、GSAP 滚动入场动画。
- 核心功能：诗人/诗词/景点/历史事件数据展示；地图可视化（文学景观分布）；关系图谱（AntV G6）；3D 场景（Three.js）；数据大屏；AI小文智能问答（RAG）；后台管理端 CRUD。

# 任务
基于上述项目，撰写一份完整、可直接作为毕业设计（论文）主体的文档，遵循高校计算机类毕业设计常见结构。

# 文档结构（标准章节，编号从第一章开始）
第一章 绪论（研究背景与意义、国内外研究现状、研究内容、论文组织结构）
第二章 相关技术与理论基础（逐项介绍 Spring Boot、Vue3、ECharts/G6/Three.js、RAG/LLM、JWT、OSS 等，并说明选型理由）
第三章 系统需求分析（可行性分析、功能需求、非功能需求、用例图/功能模块图说明）
第四章 系统设计（总体架构、后端分层与接口设计、前端模块划分、数据库 E-R 与表结构、双主题与 RAG 流程设计）
第五章 系统实现（按模块分节，每节：实现思路 + 代码占位 + 界面截图占位）
第六章 系统测试（测试环境、功能测试用例表、性能与兼容性说明）
第七章 总结与展望
参考文献、致谢

# 输出与占位符规范（关键，务必严格遵守）
1. 用 Markdown 输出，层级清晰；**所有截图与代码均用占位符标注**，便于后续人工补全。
2. 截图占位符（统一引用块 + emoji，便于全文检索 `【图`）：
   > 📷 **【图 X-Y 图题】** 说明：……（描述该截图应展示什么界面/状态）。
   > 截图来源：……（给出获取方式，如"浏览器访问 http://localhost:5175 的 /map 页面截取"）。
3. 代码占位符（便于检索 `【代码`）：
   > 💻 **【代码 X-Y 文件名/类名】** 功能：……。
   > 代码来源：`backend/src/...` 或 `display-v2/src/...`（注明真实路径，便于后续粘贴实际片段）。
   ```语言
   // TODO: 粘贴该文件关键方法（如 generateToken / parseToken / 某 composable）
   ```
4. 编号规则：图/代码编号与所在章节对应（第三章用 3-1、3-2…），全文连续且唯一。
5. 文末附《占位符清单》表格，列出所有【图】与【代码】的编号、对应章节、应补内容、来源路径，方便逐项核对补全。
6. **不凭空编造代码或运行结果**：代码只标注应取自的真实文件；测试结果为"待补"或引用仓库实际片段。截图一律用占位符——模型无法生成真实运行截图。
7. 若某小节项目信息不足，明确标注【待补充：……】而非编造。

# 风格与约束
- 学术书面语，避免口语；术语首次出现给出英文全称（如 RAG, Retrieval-Augmented Generation）。
- 现代极简、清晰层级；若后续转排版/PPT 遵循三色原则、高留白。
- 每章 800–1500 字，全文约 1.2 万–1.8 万字（可按学校要求调整）。
- 引用文献使用 [1][2] 上标，文末列出 10–15 篇真实可查的参考文献（教材 / 论文 / 官方文档）。
- 图表在正文中首次提及处就近放置占位符，并保持"见图 X-Y""如代码 X-Y 所示"的引用行文。

# 交付
最终产出 **Word 文档（.docx，本科毕业设计格式：宋体正文 / 黑体标题 / A4 / 含封面与页码）**；撰写阶段正稿使用 Markdown，经学术排版后转换为 .docx。文档开头用一句说明：覆盖章节范围、是否已按约定留占位符、共预留多少处图与代码占位。

## 补全工作流（给你的操作建议）
1. 用本提示词生成 `.md` 初稿 → 我可直接执行。
2. 按文末《占位符清单》逐项补全：
   - 代码：从仓库对应真实路径复制关键片段，替换 `// TODO` 块。

3. 批量检索：`grep -n "【图" 文档.md` / `grep -n "【代码" 文档.md` 可一键列出所有待补项。
4. 已生成 `.docx`（本科 Word 格式，含封面/目录/页码/占位符高亮）；如需进一步美化可调用对应排版技能。
